## 审查维度（逐项过，没问题也写「无」）

1. **★ A5「别烦我」与既有穿透机制的所有权冲突**（我认为本轮**最容易做错**的一条）：M0 现有 `setIgnoreMouseEvents(true,{forward:true})` + 渲染进程 `elementFromPoint` 命中测试动态开关 + **2000ms 看门狗会重断言穿透**。规格是否明确了「谁拥有 ignore 状态的最终决定权」？「别烦我」开着时，看门狗会不会把状态推翻、或命中测试把它关掉，导致两个开关互相打架？**验证规格里给出的机制能自洽**。
2. **★ A1 的 nickname 语义变更是不是破坏性的**：M0 的 `config.nickname` 默认值是「琉斯」（猫自称）。脑洞指出要摆正语义——**nickname 应该存「用户的名字」而不是猫的名字**。这是**破坏性语义变更**：老 `config.json` 里 `nickname:"琉斯"` 的用户，升级后会变成「猫管用户叫琉斯」。规格有没有给迁移策略（版本号字段 + 迁移规则 + 老文件怎么处理）？会不会打破 M0 已有用例（如「主动话术：问候带时间与昵称」）？
3. **A2 走动与既有护栏的关系**：走动「不占说话额度」——那会不会出现用户连着工作一小时、猫每 50 秒就走一次把用户烦死？禁止态清单是否完整（对话中 / 拖拽中 / 打盹 / 别烦我 / 暂停 / 全屏程序在前台 / 用户正在猛打字）？**节拍数字是否真的够安静**（拿脑洞给的数字自己算一遍：每 200ms 抽 0.4% 在 1 小时里期望约几次）？
4. **新增状态与状态机转移白名单的整合**：走动/看向是新增状态还是复用 8 方向帧？会不会破坏 M0 已测的转移断言（`tests/state-machine.test.js` 里有白名单拒绝越界迁移的用例）？转移表是否给出了新状态的全部入口/出口？
5. **A4 滚轮与既有交互的冲突面**：气泡内滚动（长文本要能滚）、设置面板滚动、拖拽中滚动——三处会不会被「滚轮改大小」劫持？
6. **A6 吸附的坐标系**：必须按 `workArea` + DIP，不能混物理像素（`HANDOFF.md` §11 记录过调度者本人在这上面算错过一次）。多屏 / DPI 缩放（本机 scaleFactor=2）下吸附会不会贴错边？
7. **A7 全局快捷键的边界**：注册失败（被别的应用占用）有没有降级路径？`Esc` **绝不能**注册成全局（会抢走所有程序的 Esc）；退出时有没有 `globalShortcut.unregisterAll()`；改键后旧键有没有注销（否则按键泄漏）；开发期热重载会不会重复注册。
8. **验收清单可信度**：`codex 自证`栏里有没有「codex 根本做不到却写进去」的项（如在无显示器容器里验 GUI、验入场动画好不好看）？有没有该验却没验的（config 迁移、护栏不被绕过、跨天重置、墙钟回拨）？**是否明确要求 M0 的 92 个旧用例一条都不许红**？**是否要求 `--self-check` 门为每个新功能加断言（门数从 18 增加）**？
9. **安全**：A8 双击复制写入剪贴板——要不要限制长度/来源（防把超长内容或敏感内容静默写进剪贴板）？气泡内容渲染是否仍走 `textContent`（M0 的 SEC-001 一票否决项）？新增的全局快捷键会不会成为「静默执行动作」的入口？
