## 为什么加这一批
M0 的毛病是「功能都在，**操作层还很粗**」。我把产品设计文档逐条核对了一遍，发现下面这些**文档里明明写了、M0 一个都没做**的操作项。它们全部属于「操作优化 / 人性化」，也就是站长要的方向。

## 增补范围（A7-A13）

### A7 全局快捷键（**本轮最高优先**，产品文档 §3.2 第 616-624 行原文）
| 快捷键 | 功能 | 可自定义 |
|---|---|---|
| `Alt+H` | 显示/隐藏 | 是 |
| `Alt+T` | 打开对话输入框 | 是 |
| `Alt+S` | 打开设置面板 | 是 |
| `Alt+M` | 静音/取消静音 | 是 |
| `Esc` | 关闭当前气泡/面板 | 否 |

**硬要求**：
- 用 Electron `globalShortcut`；**注册失败必须优雅处理**（被别的应用占用是常态）——不能静默失败，要能告诉用户「`Alt+H` 被别的程序占了」，并允许在设置里改键
- `Esc` 只在猫的窗口有焦点时生效（全局抢 `Esc` 是灾难）
- 设置面板里要有一个「快捷键」页/区块展示当前绑定 + 支持改键 + 「恢复默认」
- **注意**：全局快捷键注册失败/重复注册要在退出时 `globalShortcut.unregisterAll()`

### A8 双击气泡 → 复制文本（产品文档 §3.1 第 582 行）
复制全文到剪贴板 + 一个轻量成功提示（不能弹系统通知、不能打断）。另外：气泡里的**长文本应可选中**（M0 是否禁用了选区？确认一下）。

### A9 输入框内 `↑` 编辑上一条（产品文档 §3.2 第 633 行）
仅在输入框**为空**时按 `↑` 才回填上一条；非空时不劫持。

### A10 长按气泡 → 固定气泡（产品文档 §3.1 第 589 行）
长按 ≥1 秒 → 该气泡不再自动消失（用于长时间阅读）；再长按或 `Esc` 解除。**视觉上要能看出「已固定」**（比如一个图钉图标或边框变化），否则用户不知道它为什么赖着不走。

### A11 长按角色 → 拖拽准备视觉反馈（产品文档 §3.1 第 588 行）
长按 ≥1 秒 → 角色变半透明 + 出现「可移动」提示。**判断你是不是真需要这条**：M0 是直接拖，没有长按门槛。若你评估「直接拖更顺手」就明说砍掉它并给理由——**人性化不等于照抄文档**，能说服我就砍。

### A12 开机自启真接线
`config.json` 里已有 `launchAtLogin` 字段——**确认它是否真的调了 `app.setLoginItemSettings`**。若只是存了个字段没接通，接上；接通失败要给人话提示，不能静默。

### A13 「被打扰」的边界（**人性化设计题**，脑洞作答、包工头落规格）
这一条没有文档依据，是我认为最该想清楚的：
1. **单击的误触**：M0 单击猫就开对话。用户只是想拖它 / 只是想看它一眼时，会不会误开气泡？评估误触率，给防护方案（**但别把单击搞成要长按**——那违背人性化）
2. **绝对不该打扰的时刻**：全屏程序在前台（做汇报/看视频/玩游戏）、用户正在猛打字、网课/录屏中……列出「猫必须闭嘴且别乱动」的场景清单
3. **连续工作的保护**：用户连续工作 2 小时以上时，猫应该更安静还是更主动关心？给个判断
